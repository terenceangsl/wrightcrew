# Lessons: each incident and the rule it produced

Source: the Auto Crawler project, mainly the unattended week of 2026-10-11 to 10-19; L-35..L-44 come from the findings file `WRIGHTCREW_FINDINGS_20261021.md` (Auto Crawler, 2026-10-19..21). The numbers are as measured at the time. The source files cited for L-35..L-44 (`WRIGHTCREW_FINDINGS_20261021.md`, `LOCAL_SCORECARD.md`, `pi_mode_test_20261020.md`) are in the Auto Crawler repo, `scratch/_mentor_20261019/`, and are not shipped here. L-45..L-53 come from the Auto Crawler local-model work of 2026-11-02..07; the sources are its `scratch/_reports` chain logs, suite logs and the `tools/qa/idle_alarm.py` and `progress_dashboard.py` code, and the figures were re-measured on 2026-11-07.

| id | What happened | Rule |
|---|---|---|
| **L-01** | The handoff log grew (about 0.78 MB at the first measurement, over 4.6 MB by the end of the week), and reading it whole put a session over its context budget before it started. | Read a window (the last N entries, or grep by id), never the whole log. Keep the state file tiny. |
| **L-02** | The scheduled orchestrator ran every 6 h (later hourly); lanes finished in 20-30 min, then waited. About 1 h of work in 7.5 h. | Don't let the model idle between lanes. A driver runs them back to back; checks run hourly, and idle checks exit cheaply. |
| **L-03** | Hourly checks overlapped, with the risk of two lanes at once. | One-instance lock (a pid file plus an alive check) for drivers; a RUNNING/DONE lock file for scheduled checks. |
| **L-04** | Headless browser runs left processes behind, and image-name kills closed the user's own windows. | Close what you open by PID; report leftovers (expected 0); never kill by image name. |
| **L-05** | Unattended runs stalled for hours on approval prompts: (a) one-off exact-match allow rules never matched again; (b) `Write(...)` rules did not cover file writes (`Edit(...)` does); (c) the agent used the **PowerShell tool** while every rule was a `Bash(...)` rule; (d) a session-level "auto" toggle doesn't carry over to the next scheduled run. Stalls of 6 h, about 7 h and about 14 h, as measured from the scheduled-task run list (start time vs last activity). | See `docs/permissions.md`: a fixed health script plus prefix rules, `Edit(...)` for writes, one shell tool only, and a project `defaultMode` for the run window. Revert on return. |
| **L-06** | A check refused to launch lanes because the user sent a message mid-check ("user present"). Every remote check-in blocked building. | Only an explicit `USER_BACK` file means the user is back. Remote messages don't count. |
| **L-07** | An agent's "auto mode" safety classifier blocked the agent from creating or starting an unattended agent loop, and from editing its own permissions. | Correct. The **user** starts the driver and edits permissions. Agents write the scripts and tell the user the one command. |
| **L-08** | Backups were taken after the edit, so they were byte-identical to live and recovered nothing. | Back up before the first touch; prove the backup differs after the edit. |
| **L-09** | A kit's "landed" snapshots predated a newer landing; its restore would have silently erased that landing. Caught by a checker, three times. | Restore only from this card's own snapshot, taken after GREEN, md5-pinned and re-checked before each restore. |
| **L-10** | `grep -c FAIL` gates miscounted. | The gate is the suite's own summary line, N==M. |
| **L-11** | Story-row cards stopped again and again: the card forbade editing a landed assert that the change necessarily moved (25 → 29 rows), and exact-count exits were unsatisfiable. FS7 took 4 tries, HS-3 took 5, TU-1 took 3 before a checker found it. | The card must license the edits its change forces. Use measured pairs, not fixed counts. After 2 stops of the same family, park it. |
| **L-12** | Prompts written by a maker had at least one real flaw a fresh checker caught, every time: a wiring script that silently dropped a probe from the suite, stale-snapshot restores, mutations predicted to fail the wrong test, a "flag ON" simulation that tested nothing. | **If you are the maker, you need a checker.** No exceptions; the checker is a fresh session. |
| **L-13** | The mentor re-decided a locked user ruling (ship-cell size) from a stale note. The checker caught it. | Scan the locked-decision index before deciding; delegated decisions are provisional. |
| **L-14** | New features landed unreviewed; flag-OFF safety held because everything shipped behind OFF flags. But a settings checkbox then exposed every flag-ON bug to players. | Ship new features OFF. Treat "a toggle exists" as "players can reach it": review flag-ON paths before adding toggles. |
| **L-15** | A requested change of the project's permission mode from inside the agent was refused (self-modification). | The user changes permissions. Provide a user-run helper script plus a revert command. |
| **L-16** | Holding a queue item by renaming it while the driver ran it would have crashed the driver at the lane end (its rename of a missing file). | One state file, changed only through the driver CLI. |
| **L-17** | A refill lane wrote its prompt under the same filename as another maker's, overwriting it after that version was checked. | `ls` before writing; never overwrite; new name on collision. Re-check the file actually on disk. |
| **L-18** | A lane hung until its 4 h timeout killed it (rc 124): bash expanded `$_` inside a double-quoted `powershell -Command`, and PowerShell without `-NonInteractive` waited for input forever. | A shell-safety block is injected into every lane's launch text; wrap risky commands in `timeout`. |
| **L-19** | About two dozen landings went unreviewed for days; the end-of-week audit of 23 commits found 4 IMPORTANT bugs (one visible to every player) plus a 5th the audit missed, and tests that could not catch them (0 ticks pumped; header text never asserted). | Review each landing as it lands. Every fix ships with a test that is RED on the old code. |
| **L-20** | Without the goal list in the refill prompt, the planner refill kept picking low-value cards. With the v1 list added, the element wheel, the evolution tree and the tutorial all landed within about 3 days. | The refill priority list = the project's real goal list, kept current. |
| **L-21** | A lane timeout killed the runner but left the agent's child processes alive. | The runner kills the whole process tree on timeout (a Windows Job Object with kill-on-close). |
| **L-22** | A local LLM ran 19-69 lane starts a day unattended (driver log; 250 over the week, about 30% refill/docs lanes), with 1 outright failed item in the whole queue; many builder lanes ended in a clean CARD-CONFLICT stop. | A clean stop is cheap and safe; the waste is in unchecked cards. Check first. Resume the lane's session for the retry instead of a cold start (planned). |
| **L-23** | A rename and new README text were added after a RELEASE check and never re-checked. The re-check found 2 false claims, a quick start that failed at the first lane, and a lock race. | Any change after a check, docs included, reopens the check. Re-check the diff before calling it released. |
| **L-24** | README numbers were cherry-picked ("44–69 lanes a day" when full days ran 19–69), and an absolute claim ("every mistake caught") contradicted the project's own L-19. | Every number in user-facing text cites the measurement. No absolute claims. The README must not contradict `lessons.md`. |
| **L-25** | The quick start had never been followed literally, and it left out the runner file. | A checker walks the quick start step by step in a fresh throwaway project. |
| **L-26** | A guard documented as "enforced by the code" accepted maker == checker, and a pid lock was written in two steps and deleted without an owner check. | Each enforcement claim has a test that shows the refusal. Locks are written atomically and deleted only by their owner. |
| **L-27** | A subagent's shell hung for about 27 h (`python3 - <<EOF … \|\| python - <<EOF2` on Windows, where the `python3` app-store stub waited on stdin). It was found only when the user asked to close all sessions. | At the end of every run, list the processes agents started (by command-line marker) and kill them by PID. Never chain heredoc interpreters with `\|\|`. |
| **L-28** | One scheduled-task run stayed "running" for about 26 h. The scheduler started no new runs, so every check stopped, and nobody noticed: the driver kept building without one. | The mentor reads the scheduler's run list each session. A run older than its interval is stuck and gets stopped. A missing check report is an alarm. |
| **L-29** | Agent simulation copies (a `run_checks.sh` copy and a script with a browser launch line) were written inside the repo. They broke the repo lint and blocked 3 live lanes. Separately, a lane committed an evidence script that failed lint and blocked the lanes after it. | Maker and checker copies live outside the repo. Lint runs before every commit. |
| **L-30** | A lane exited rc 0 mid-run and left a half-edited test file, which would have blocked every later card. | rc 0 isn't "landed". The driver requires a `[CARD-ID]` commit; without one the item is `failed` (note `no [ID] commit`). If the lane left guarded files dirty, all builder lanes stay blocked until a human cleans the tree (driver.log shows BLOCKED); automatic handling is planned for v0.5. |
| **L-31** | Paid extra usage grew while the weekly figure was 53%, because the checks ran hourly and overflowed the short (5-hour) usage window, and the guard watched only the weekly window. | Budget guards watch the shortest window too. Agent waves stop well below it (60–80%). See `docs/budget.md`. |
| **L-32** | Every new feature shipped default-OFF. That was safe, but a new player saw none of the week's work. | OFF-by-default is the landing state, not the finish. Each flag needs a scheduled default-ON decision. |
| **L-33** | The mentor who checked Wrightcrew was then asked to fix it. It handed the fix to a fresh maker and the re-check to a different fresh checker, so nobody checked their own work, and it waited for the usage reset before launching them. | A reviewer never fixes what it reviewed. Under budget pressure, draft first and launch after the reset. |
| **L-34** | Pairing paid and local models worked: Claude spent tokens on plans and checks, and the local model ran 250 lane starts over 7 calendar days (5 full days) for free. Every Claude-written prompt went through a fresh checker before a local lane ran it. | The expensive model checks; the cheap model builds; a check stands between them every time. |
| **L-35** | A local model was brought up by guidance alone, with no fine-tuning: a per-role lessons file, a recipe written by a strong model, automatic gates and a scorecard. Code-card findings fell from 4 Important (card 3) to 1 minor (card 5); art went from mostly failing hand-drawn screens to 5 of 5 zone screens passing every gate on the first try once a recipe existed. | Train a local model with guidance, not weights. See `docs/guidance.md`. Finding 1 (source: findings file; `LOCAL_SCORECARD.md`). |
| **L-36** | A Claude "art director" made one quality-bar example plus a recipe; the local lanes then repeated it for 7 zones (findings file item 2). Separately, one batch made 20 creature sprites in 31 min (`LOCAL_SCORECARD.md`, one sprite batch). | The art director sets the bar once; the local model does the volume. Finding 2. |
| **L-37** | Lanes passed every numeric gate while the art was flat, plaid, or the creature had lost its signature features. | Gates passing is not quality. Vision-model lanes must look at their own output (a fixed question list, before/after); signature features must be visible at 1x; a human or strong-model taste check closes each batch. Finding 3. |
| **L-38** | Every gate was eventually gamed or missed something: a "busy surface" metric was met by a perfect grid (plaid); a colour-connectivity check failed on rich art; a halo gate said 0 while halos were visible. | When a human sees a defect the gate missed, first make the gate FAIL on it, then fix the work. Finding 4. |
| **L-39** | In 2026-10-19..21 an independent checker found at least one real defect in every landed code card (a setting reset, Esc order, z-order above forced scenes, a probe that could not see what it tested, probes silently weakened). Sonnet checkers were good enough; keeping the orchestrator alone on Opus saved the most usage. | Keep the maker/checker split for every card. A Sonnet checker is enough for routine cards. Finding 5; reinforces L-12, L-19. |
| **L-40** | `pi -p` (text mode) returned 0 bytes on a run cut off at 25 s, while `--mode json` kept 354,378 B of partial work and says why the run ended (`agent_settled`, `stopReason`). `pi` with an open stdin hung with no output and no error in both modes (180 s, rc 124). A 40k-event JSONL log is too big to read whole. | Run `pi` with `--mode json` and a closed stdin. Summarise lane logs with `tools/lane_summary.py`, never read them whole. Finding 6 (source: `pi_mode_test_20261020.md`). |
| **L-41** | PowerShell code inside bash double quotes: bash expanded `$_`, PowerShell tried to run the resulting path, and Windows opened "Pick an app" dialogs on the user's desktop (22 seen). | Single quotes or a `.ps1` file. Count processes by PID, never by image name. Finding 7; extends L-04, L-18. |
| **L-42** | One lane looped for 424 turns / 2.5 h. A lane appended its own lesson to the orchestrator's lessons file. The findings file also sets the rule that the 3-fix-cycle cap has no "it's a new failure" exception (findings file item 8). | Cap each lane (90 min). The 3-fix-cycle cap has no new-failure exception. Lanes never edit the orchestrator's files. Finding 8; extends L-17. |
| **L-43** | Extra paid usage grew when the weekly figure reached 98-100 % (findings file item 9; it does not record which window overflowed). | Watch both the 5-hour window and the weekly one. Draft now, launch after the reset; prefer the free local model whenever it is idle. Finding 9; reinforces L-31. See `docs/budget.md`. |
| **L-44** | Taste calls (style, camera, sprite size) were settled by side-by-side try-outs in the real game view, not by argument. Story decisions came before art decisions. | The user's eye is the final gate. Settle taste with side-by-side try-outs in the real view; decide the story first, then the art. Finding 10. |
| **L-45** | A watcher with a self-exit timer and no restarter stopped silently. The progress dashboard's refresher had a 12 h cap; it stopped at about 11:20 (the 12 h cap is the likely cause, not proven) and at 14:39 the page was 3 h old (both times are from the mentor session transcript, not a log) and showed finished lanes as live until the user noticed (2026-11-07). | Every watcher gets a restarter (a keepalive that checks by command line) and a client-side stale banner that fires when the page's own timestamp is old. A cap on runtime is a safety feature only if something brings the watcher back. |
| **L-46** | The orchestrator reported 'hours of work queued' from card estimates. Reconstructed from the lane chain logs for the 36 h to 2026-11-07 22:49: about 60 lanes, median about 28 min, and about 9.8 h in total (counting every gap) with no lane running on either machine (about 7 h of it between 19:59 and 07:41). Start times come from log timestamps and end dates from file times, so treat the figures as approximate. | Never state queued hours without computing them from measured lane durations. Keep work in backlog files that a refill supervisor drains, and read the queue state file back after every 'queued' or 'started' claim (the same session once said audits were queued when they were not). |
| **L-47** | An idle alarm that could not wake the orchestrator was useless: launched detached by a keepalive, it fired and wrote its banner, and no lane then ran on either machine for about 112 min (lane-log gap 15:07 to 16:59 on 2026-11-07). The alarm record read 110 min (A) and 113 min (B) but was overwritten later, so those two figures are not re-checkable. A stall check that only trusts the queue file misses a crashed lane; one that trusts a silent log gives false alarms for a harness that buffers output (a harness can buffer its log until the end). | The alarm must be a tracked background task whose exit notifies the orchestrator, and it must be re-armed after every fire. Detect a stalled lane by the lane's newest log time AND the model server's own busy flag (llama.cpp /slots is_processing), not by either alone. |
| **L-48** | Relaunching the desktop app killed the lanes, refill supervisors and watchdog that had been started from a shell with nohup. Processes started with a hidden detached launcher (PowerShell Start-Process -WindowStyle Hidden) survived. The 'safe to relaunch' advice was wrong. | Start long-running machinery with a detached launcher, not a shell child. After any app restart, list the processes first and restart what is missing before saying anything is running. |
| **L-49** | A cross-machine audit (A checks B, B checks A) added waiting but no independence, because both machines serve the same model. A fresh-session audit queued on the same machine right behind the build did the same job without the wait. A separate fresh checker running the BUILT game found layout defects (a tooltip slot covering the inventory at a small viewport; the exact size was not re-checked) that every probe and every lane audit had passed. | Audit with a fresh session (no shared context, read-only, different card) on the same machine, queued behind the build. Add one behavioural check of the built artifact per batch by a different, stronger reviewer. The builder never audits or fixes its own audit. |
| **L-50** | A change that copied a target template exactly (wider side columns, smaller key letters, new bar colour) turned several existing probes red (the count was not re-checked) and contradicted an earlier user ruling about stage width. The builder correctly did not edit the probes; the checker named the conflict. | When a change contradicts a recorded user ruling or an accessibility threshold in a probe, stop and surface the conflict with numbers. Re-issue a probe only after the ruling is changed in words, with the override and its scope written next to the new assert. |
| **L-51** | Generated files that were stale after concurrent lanes (the code map, test sidecars, the built bundle) made the full suite show 8 failing checks against an allowlist of 6 (suite logs of 2026-11-05 and 2026-11-06); a later run on 2026-11-06 showed 6. Other runs in the same days showed 5 to 25 failing, so this pair is one example, not the whole range. That the stale files caused the extra two is the mentor's explanation and was not re-measured. | Regenerate every generated file and rebuild the artifact before the one full suite run, and compare reds by NAME against the accepted list, not by count. |
| **L-52** | Three finished audit lanes (chk11, chk12, chk13; each report ends with `status: done`) were still run through all 3 attempts by the chain driver, and chk11 to chk13 ended EXHAUSTED. The resume prompts named `scratch/lanes/20261105/chkNN/report.md`, an empty folder, while the lanes wrote to `20261107`. The driver's `finished` check read None each time. The extra attempts took 2.5 to 5 min each. The link between the wrong path and `finished=None` is likely but was not proven. | The launcher checks that the report path in the prompt is the folder the lane will write to, and the chain driver warns or stops when the report file does not exist after an attempt. |
| **L-53** | After a long session the mentor could not recall facts stated days earlier, although the transcript and the repo held them. | Keep the small state file named in AGENTS.md section 2 current at every milestone and read it first after any compaction; search saved transcripts before saying 'I forgot'. |
