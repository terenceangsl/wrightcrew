# Lessons: each incident and the rule it produced

Source: the Auto Crawler project, mainly the unattended week of 2026-10-11 to 10-19. The numbers are as measured at the time.

| id | What happened | Rule |
|---|---|---|
| **L-01** | The handoff log grew (about 0.78 MB at the first measurement, over 4.6 MB by the end of the week), and reading it whole put a session over its context budget before it started. | Read a window (the last N entries, or grep by id), never the whole log. Keep the state file tiny. |
| **L-02** | The scheduled orchestrator ran every 3 h; lanes finished in 20-30 min, then waited. About 1 h of work in 7.5 h. | Don't let the model idle between lanes. A driver runs them back to back; checks run hourly, and idle checks exit cheaply. |
| **L-03** | Hourly checks overlapped, with the risk of two lanes at once. | One-instance lock (a pid file plus an alive check) for drivers; a RUNNING/DONE lock file for scheduled checks. |
| **L-04** | Headless browser runs left processes behind, and image-name kills closed the user's own windows. | Close what you open by PID; report leftovers (expected 0); never kill by image name. |
| **L-05** | Unattended runs stalled for hours on approval prompts: (a) one-off exact-match allow rules never matched again; (b) `Write(...)` rules did not cover file writes (`Edit(...)` does); (c) the agent used the **PowerShell tool** while every rule was a `Bash(...)` rule; (d) a session-level "auto" toggle doesn't carry over to the next scheduled run. Stalls of 6 h, about 7 h and about 14 h, as measured from the scheduled-task run list (start time vs last activity). | See `docs/permissions.md`: a fixed health script plus prefix rules, `Edit(...)` for writes, one shell tool only, and a project `defaultMode` for the run window. Revert on return. |
| **L-06** | A check refused to launch lanes because the user sent a message mid-check ("user present"). Every remote check-in blocked building. | Only an explicit `USER_BACK` file means the user is back. Remote messages don't count. |
| **L-07** | An agent's "auto mode" safety classifier blocked the agent from creating or starting an unattended agent loop, and from editing its own permissions. | Correct. The **user** starts the driver and edits permissions. Agents write the scripts and tell the user the one command. |
| **L-08** | Backups were taken after the edit, so they were byte-identical to live and recovered nothing. | Back up before the first touch; prove the backup differs after the edit. |
| **L-09** | A kit's "landed" snapshots predated a newer landing; its restore would have silently erased that landing. Caught by a checker, three times. | Restore only from this card's own snapshot, taken after GREEN, md5-pinned and re-checked before each restore. |
| **L-10** | `grep -c FAIL` gates miscounted. | The gate is the suite's own summary line, N==M. |
| **L-11** | Story-row cards stopped again and again: the card forbade editing a landed assert that the change necessarily moved (25 → 29 rows), and exact-count exits were unsatisfiable. FS7 took 4 tries, HS-3 took 5, TU-1 took 3 before a checker found it. | The card must license the edits its change forces. Use measured pairs, not fixed counts. After 2 stops of the same family, park it. |
| **L-12** | Prompts written by a maker had at least one real flaw a fresh checker caught, every time: a wiring script that silently dropped a probe from the suite, stale-snapshot restores, mutations predicted to fail the wrong test, a "flag ON" simulation that tested nothing. | **If you are the maker, you need a checker.** No exceptions; the checker is a fresh session. |
| **L-13** | The mentor re-decided a locked user ruling (ship-cell size) from a stale note. The checker caught it. | Scan the locked-decision index before deciding; delegated decisions are provisional. |
| **L-14** | New features landed unreviewed; flag-OFF safety held because everything shipped behind OFF flags. But a settings checkbox then exposed every flag-ON bug to players. | Ship new features OFF. Treat "a toggle exists" as "players can reach it": review flag-ON paths before adding toggles. |
| **L-15** | A requested change of the project's permission mode from inside the agent was refused (self-modification). | The user changes permissions. Provide a user-run helper script plus a revert command. |
| **L-16** | Holding a queue item by renaming it while the driver ran it would have crashed the driver at the lane end (its rename of a missing file). | One state file, changed only through the driver CLI. |
| **L-17** | A refill lane wrote its prompt under the same filename as another maker's, overwriting it after that version was checked. | `ls` before writing; never overwrite; new name on collision. Re-check the file actually on disk. |
| **L-18** | A lane hung until its 4 h timeout killed it (rc 124): bash expanded `$_` inside a double-quoted `powershell -Command`, and PowerShell without `-NonInteractive` waited for input forever. | A shell-safety block is injected into every lane's launch text; wrap risky commands in `timeout`. |
| **L-19** | About 26 landings went unreviewed for days; the end-of-week audit found 4 IMPORTANT bugs (one visible to every player) plus a 5th the audit missed, and tests that could not catch them (0 ticks pumped; header text never asserted). | Review each landing as it lands. Every fix ships with a test that is RED on the old code. |
| **L-20** | Without the goal list in the refill prompt, the planner refill kept picking low-value cards: 11 lanes, 1 landing. With the v1 list added: element wheel, evolution tree, tutorial, all landed within a day. | The refill priority list = the project's real goal list, kept current. |
| **L-21** | A lane timeout killed the runner but left the agent's child processes alive. | The runner kills the whole process tree on timeout (a Windows Job Object with kill-on-close). |
| **L-22** | A local LLM ran 44-69 lanes a day unattended (driver log), with 1 outright failed item in the whole queue; many builder lanes ended in a clean CARD-CONFLICT stop. | A clean stop is cheap and safe; the waste is in unchecked cards. Check first. Resume the lane's session for the retry instead of a cold start (planned). |
